# Proposal

## Why

プロジェクトはオープンソースの技術レーダーとして位置づける：技術市場を観察し、技術選定を支援する。トップページには現在検索ボックスが 1 つあるだけで、探索の入口もなく、`daily-snapshot` が蓄積したデータの表示もない。この change はトップページに 3 カラムの骨格を与え、6 大分類をワンクリックの探索入口にし、スナップショットデータから 2 つのランキングを作る：Most Popular と、実際の 30 日増分に基づく Rising Stars である。ランキングは静的 JSON を読み、API クォータを消費しない。

## What Changes

- トップページを 3 カラムレイアウトに変更する：左カラムはナビゲーション（分類。今後は種別切替とフィルタを置く）、中央カラムは検索と結果、右カラムはランキング。狭い画面では単一カラムに退化する：分類は横並びの chip 行になり、ランキングは結果の下に移る。キャッチコピーとレーダーのイラストは上部に残す。
- 分類マッピングファイルを新設する：6 つの分類（Frontend、Backend、AI / ML、DevOps、Database、Design）がそれぞれ 1 本の GitHub クエリ（topic 主体）、1 つのアイコン、3 言語の名称に対応する。分類のクリックはそのクエリの送信と同等である。
- 2 つのランキングを新設し、データは `public/data/` から取る：Most Popular はスナップショット内の star 数で並べる。Rising Stars は直近 30 日の star 増分で並べる（系列が 7 日に満たない場合は、直近 90 日以内に作成されたリポジトリを star 順に並べる方式に退化し、注記を付ける）。それぞれ上位 5 件を取り、現在の分類でフィルタし、「すべて表示」で上位 30 件に展開できる。ランキングは API リクエストを発行しない。
- ランキング領域にデータ日付を表示する。スナップショットデータが欠けているか 3 日を超えて古い場合は注意を表示し、メインの検索には影響しない。
- 現在の分類をハイライトする。分類外の検索ではどの分類もハイライトしない。
- 本 change 完了後に単独で git commit する。

## Capabilities

### New Capabilities

- `category-browse`: 分類の集合、各分類に対応するクエリ、ナビゲーションの表示とクリック時の挙動。
- `rankings`: Most Popular と Rising Stars の 2 つのランキングの定義、データソース（スナップショット）、増分計算、表示と「すべて表示」。
- `discovery-layout`: トップページの 3 カラムレイアウトの各ブレークポイントでの構造と、各領域に何を置くか。

### Modified Capabilities

- `daily-snapshot`: レコードに owner の数値 id を追加し、アバター CDN のアドレスを直接組み立てるのに使う（2026-10-21 追加）。
- `ui-theme`: 初回訪問時のデフォルトをダークに変更し、システム設定には従わない（2026-10-21 のレイアウトと表示調整フェーズで追加）。

## Impact

- `daily-snapshot` が提供する `src/lib/categories.ts` と `public/data/` に依存する。`src/lib/snapshot/`（JSON の読み込みとデコード、増分計算）と `src/lib/rankings.ts`（並び替えルール）を新設する。
- `CategoryNav`、`RankingList` コンポーネントと 6 つの分類アイコンを新設し、`HomePage` を 3 カラムテンプレート `DiscoveryLayout` に変更する。
- `useSnapshot` hook を新設する（`latest.json` と必要な series を 1 回だけロードし、メモリにキャッシュする）。
- 3 つの言語ファイルに `category.*`、`ranking.*` キーを追加する。
- トップページのコールドロードで静的 JSON リクエストが 2 つ増えるが、GitHub API クォータは消費しない。
